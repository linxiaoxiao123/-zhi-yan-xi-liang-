# Coze 插件 + 智能体搭建指南

> 目标：把后端「分析聚合接口」封装成 Coze 插件，再挂到一个智能体上，实现"用大白话问浪费情况，智能体调数据、组织语言回答"。

---

## 一、内网穿透（前置）

后端现在跑在 `http://127.0.0.1:8000`，Coze 在云端调不到它，得先穿透。

用 **cpolar**（免费、国内、免备案）举例：

1. 注册 cpolar，下载安装。
2. 本地起一个隧道，把 8000 端口映射出去：

```powershell
cpolar http 8000
```

3. 终端会显示一个公网地址，形如 `https://xxxx.cpolar.top`。**记下这个地址**，后面要用。

> 注意：免费隧道每次重启地址会变，Coze 插件里要同步改 `servers.url`。答辩当天建议现起现用。

---

## 二、建 Coze 插件

1. 打开扣子（Coze）→ 左侧「插件」→ 「创建插件」。
2. 选「通过 OpenAPI 导入」（或「从 OpenAPI 创建」）。
3. 上传 `openapi.json`（就在本目录）。
4. **把 `servers.url` 里的 `https://你的内网穿透地址.cpolar.top` 改成你真实的穿透地址**。
5. 鉴权方式先选「无需鉴权」（后端目前没有鉴权，后面再补）。
6. 保存并发布插件。

---

## 三、建智能体（Bot）

1. Coze 首页 → 「创建智能体」。
2. 模型选豆包（如 doubao-seed 或 1.5 pro）。
3. 在「人设与回复逻辑」里粘贴下面这段：

```
你是「智眼惜粮」食堂餐食浪费智能分析助手，服务对象是食堂管理员。你的职责是分析餐食浪费数据、找出问题菜品并给出可执行的改进建议。

你拥有「餐食浪费分析」插件，能获取真实检测数据（总次数、平均剩余占比、高浪费条数、菜品浪费排行、趋势、浪费等级分布）。

回答规则：
1. 涉及浪费概况、哪个菜浪费最狠、浪费趋势、改进建议时，必须先调用插件拿真实数据，绝不编造数字。
2. 用简洁专业的口语，像食堂营养师在向管理员汇报，不要堆砌术语。
3. 改进建议要落到具体菜品：如米饭出现频繁且浪费高→建议减量或提供小份；油炸类（鸡米花）浪费率高→建议调整口味或份量。
4. 如果插件返回近期无数据（趋势全为0或总数为0），如实说明"近期暂无检测数据"，不要硬编。
5. 用户可以追问，你要结合数据继续深入（比如"那米饭怎么改进"）。

回答结构（分点，简洁）：
- 浪费概况：总次数、平均剩余占比、高浪费占比
- 问题菜品：浪费最狠的几种菜 + 具体数据
- 趋势：如果有数据就提，没有就跳过
- 改进建议：2-3 条可执行的
```

4. 在「插件」标签里，把刚才建的「餐食浪费分析」插件加进来。
5. （可选）建一个知识库，塞几篇「节约粮食」「食堂精细化管理」的文档，让智能体给建议时能引用政策。
6. 发布智能体。

---

## 四、测试

在 Coze 的预览/调试窗口里问：

```
今天食堂的浪费情况怎么样？哪个菜浪费最狠？给我点改进建议。
```

预期：智能体会调用插件 → 拿到 `overview` 和 `top_wasted_foods` → 组织成类似：

> 目前共检测 662 次，平均剩余占比 45.4%，高浪费记录 291 条。浪费最严重的是米饭（出现 577 次、平均剩余 62.9%），其次是酸甜鸡米花（79%）。建议米饭提供小份选项、鸡米花调整份量……

看到它引用了真实数字，就说明插件链路打通了。

## 五、前端接入（可选，后续再做）

前端那 5 个页面的 `API_BASE_URL` 已经能通过 `.env` 的 `VITE_API_BASE_URL` 配置。若要让前端「AI 助手」对话框走 Coze，需要把原来调 `/api/ai/global-analysis` 的地方改成调 Coze 的 Bot API（需要 Coze 的 API token）。这步等插件和智能体跑通后再做。
